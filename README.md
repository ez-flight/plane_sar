# plane_sar

Программная реализация статьи «Методика текущего планирования радиолокационной съёмки
сложнораспределенных объектов района» (v8): планирование съёмки сложнораспределённых
объектов (СРО) группировкой КА с РСА в гибридном электромеханическом режиме за один пролёт
и на горизонте нескольких суток.

Основа — [sar-angle-calculator](https://github.com/ez-flight/sar-angle-calculator): из него
перенесены без изменений преобразования координат (`calc_cord.py`), эфемериды SGP4 через
pyorbital, геометрия съёмки и окна видимости (`sar_model/`), загрузка TLE (`read_TBF.py`)
и программа `run_sar_model.py`. Новая часть — пакет `sarplan/`.

## Что реализовано

| Модуль `sarplan/` | Содержание | Формулы статьи |
|---|---|---|
| `frames.py` | ECI ↔ ECEF ↔ геодезические (WGS-84, как в `calc_cord`), локальные оси, смещение точек | — |
| `orbit.py` | Синтетические TLE для ССО (МВВУ, фаза), SGP4 через pyorbital, поиск пролётов над районом | — |
| `duration.py` | Длительность наблюдения кадра: замкнутая форма с поправкой при ϑ₁ > π, численный интеграл, уравнение Кеплера; исправленный ε и ε в виде [4]; N_обз и N_max | (1)–(5), (9), (19) |
| `geometry.py` | Оси крен/рыскание/тангаж, пересечение луча с эллипсоидом, Δβ_ск, Δβ_ум, β_ск, β_ум, доплер | (10)–(15) |
| `targets.py` | Элементы СРО (точка, линия, площадь), кадры-кандидаты, сценарии статьи, ось Днестра | — |
| `gis.py` | Чтение линий из GeoPackage (`Днестр.gpkg`) без GDAL: SQLite + разбор WKB | — |
| `windows.py` | Окна видимости и допустимости Ω_k(R_Tп), сетка точек наведения Ξ, показатель Φ_k, кластеризация (Жаккар, иерархическая) | (17) |
| `criterion.py` | Взвешенное покрытие с насыщением и директивными сроками χ_i(t) | (16) |
| `planner.py` | Жадная вставка по ρ_k с локальным улучшением, точный перебор подмножеств, внешний цикл по точкам наведения; базовые методы: жадный по приоритету, аналог [2], аддитивное ДП [5, 6], планировщик без модели допустимости | (18), (19) |
| `rolling.py` | Скользящий горизонт: события, фиксация T_фикс, штраф κ за изменение решений, доля Д | (20) |
| `constellation.py` | Группировки 1/3/6/12 КА (плоскости 10:30, 14:30, 6:00, 18:00), распределение кадров по пролётам | — |
| `experiments.py` | Воспроизведение таблиц 3–7 и рисунков 1–2 | — |
| `cli.py` | Командная строка | — |

Параметры малого КА (таблица 2) и пресеты «Обзор-Р» и «Кондор-ФКА» — в `sarplan/config.py`.

## Установка

```bash
pip install -r requirements.txt
```

## Запуск

План съёмки по своей заявке (элементы СРО, КА, горизонт — в YAML):

```bash
python -m sarplan plan config/plan_example.yaml
```

Результат: `result/plan/plan.csv` (КА, время начала кадра, кадр, углы β_ск, β_ум, Δβ_ск, Δβ_ум,
точка наведения) и `result/plan/summary.json` (покрытие по элементам и пролётам).
КА задаются синтетически (МВВУ, фаза) или файлом TLE (`satellites.tle_file`, `norad_ids`).

Воспроизведение расчётов статьи:

```bash
python -m sarplan experiments               # все таблицы и рисунки -> results/
python -m sarplan experiments table3 table5 # выборочно
python -m sarplan experiments --quick       # меньше наборов, для быстрой проверки
```

Доступные эксперименты: `duration` (проверка (3) и рис. 1), `table3`, `duplicates`,
`sensitivity`, `table4`, `table5`, `line21`, `table6` (и рис. 2), `table7`.
Сводный отчёт — `results/REPORT.md`.

Тесты:

```bash
python -m pytest tests
```

Базовый комплекс из sar-angle-calculator запускается как раньше:
`python run_sar_model.py config/sar_model_config_example.yaml`.

## Допущения

- Эфемериды — SGP4 (pyorbital). Для гипотетических КА класса ICEYE и группировок TLE
  синтезируются из элементов круговой ССО высотой 560 км.
- Вся геометрия считается в ECEF; скорость КА — относительно вращающейся Земли, V_отн из (15).
- Углы Δβ_ск и Δβ_ум считаются по проекциям на плоскости, ортогональные осям тангажа и крена,
  как в (13), (14); модуль совпадает с arccos(...), знак — ориентированный угол от оси антенны к цели.
- Точка наведения R_Tп = C + l_с·a + h_п·u: C — центр района, a — направление вдоль трассы,
  u — линия визирования центра на траверзе. Номинальная глубина h₀ выбирается так, чтобы пятно ДН
  прошло протяжённость района по азимуту за бюджет T_вкл max; сетка Ξ — 7 смещений × 6 глубин.
- У КА большого класса механического вращения нет: окно задаётся электронным сектором по скосу
  относительно траверза.
- Ось Днестра берётся из `Днестр.gpkg` (OpenStreetMap): участок от устья вверх по течению, рамки
  ставятся по руслу с шагом 4,9 км по прямой, поэтому 21 рамка покрывает меандры от устья до района
  Тирасполя. Без файла используется приближённая ломаная. В YAML-заявке линию тоже можно взять из
  gpkg (`gpkg`, `from`, `length_km`, см. `config/plan_example.yaml`).
- Сценарии синтетические, поэтому числа близки к статье по характеру, но не обязаны совпадать до знака.
